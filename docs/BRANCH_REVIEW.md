## 先看这些变化

- **查找与整理**：当前故事正文搜索、快捷键、故事和资料筛选、兼容全角及重音字符、单条正文复制。
- **减少重复填写**：复制模型连接、角色和主角资料；导出文件名包含故事标题；侧栏标记未发送草稿。
- **保护编辑成果**：跨故事草稿隔离，离开页面和关闭记录先保存，更新应用先征得刷新操作，上传头像不覆盖同时编辑的文字。
- **记录更好用**：最新检查点优先、详情按需读取、分批展开旧历史、保留记录页签和展开状态、来源跳转真正露出正文。
- **避免异步串页**：旧请求不覆盖新故事或新设置，重复打开当前故事不停止生成，切换消息版本时不显示可编辑的旧状态。
- **后台减少无用读取**：聊天导航用摘要、沿当前消息链查询、只读取需要的 Memory 和状态正文、精简 Trace/SSE 查询、补充索引和批量查询。

## 如何检查

1. 在项目目录运行 `Start.cmd`，或者执行 `pnpm start`；当前分支的前后端已重新构建。服务启动后刷新网页，已安装的 PWA 可关闭后重开。
2. 日常界面项可用新建的临时故事检查。若要全程不调用模型，开启手动输入，并把 Memory 和主角状态自动更新间隔设为 0；“生成”“更新”“测试连接”等显式按钮仍可能调用配置的模型。
3. 标为 **技术复核** 的项目涉及断网、延迟、服务停止、供应商异常或 SQL，适合使用离线演示、模拟请求和临时数据库。不要为验收中断正在使用的正式故事；普通使用只能观察结果，不能证明性能收益。
4. 每项检查通过后将 `[ ]` 改为 `[x]`；有问题就记下编号、操作和实际结果。无需一次性重跑全部自动化测试。
