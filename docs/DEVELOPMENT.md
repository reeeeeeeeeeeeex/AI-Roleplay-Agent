# 开发流程

## 验证

- 只检查改动涉及的关键路径和具体高风险错误；涉及类型或接口时按需做类型检查。纯文档修改只检查文字、链接和差异。
- v0.2 最多保留 8 项聚焦验证，优先修改现有测试；删减重复、低价值测试，不以大测试藏大量子用例，不跑全量回归。
- 局部修改不默认增加浏览器截图、真实语料或真实模型评测；默认验收使用临时离线数据和模型夹具。
- 不为“证明没有变化”做全目录 SHA-256 扫描、导入前后哈希比对或重复校验。删减哈希时先确认它是否承担资源寻址、导入去重等实际功能，必要时连同依赖处理。

## 运行中交付

- 前端改动若交付到读取 `apps/web/dist` 的服务，先重新构建，再从实际服务地址确认首页和 PWA Service Worker 引用了新资源；提醒用户刷新或重开已安装应用。
- 服务端改动交付到运行中的服务时，重新构建并重启对应进程，确认实际请求使用了新代码。
- 每次为验收启动或重启服务，结束、失败或中断后都须清理本次服务、启动器和测试后台进程。关闭前核对 PID 与命令行，只处理本项目、本次验收的进程，并确认服务端口与测试端口释放。
- 除非用户明确要求保持运行，交付时说明本次服务已关闭，由用户自行启动。

## 发布

- 发布前用解压后的包和临时离线数据验收，关闭验收进程并确认端口释放后再发布；构建产物仅作为 Release 附件。
- 发布包不增加用户安装要求；macOS／Linux 启动脚本保持 LF。
